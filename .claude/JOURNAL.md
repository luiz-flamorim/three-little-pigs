# Journal

A running, plain-language log of the real decisions made while building this project. Maintained by the `journal-keeper` agent. New entries are appended at the bottom, in chronological order.

## 2026-10-16

- **Project boundary rule**: created `.claude/instructions.md` as the shared rules file for all agents, with Rule 1 stating that agents must never read, write, or operate outside this project's root folder, even for temporary or test files.
- **Chosen demo concept**: decided the mentorship programme's final piece would be a retelling of The Three Little Pigs fable, used to test and demonstrate multi-agent LLM interaction, each agent holding its own refinable persona.
- **Initial agents created**: added five persona files under `.claude/agents/`: `storyteller.md`, `pig-straw.md`, `pig-sticks.md`, `pig-bricks.md`, and `wolf.md`, each with a first-paragraph persona matching the classic fable roles.
- **Markdown readability rule**: added Rule 2 to `.claude/instructions.md` requiring every project markdown file to be written as complete, continuous paragraph strings, with no mid-paragraph hard line breaks.
- **Pig action rules**: defined gamified behavior for the three pigs — run from the wolf when outside a shelter, attempt to build their house once and flee to the next house on failure, and defy or mock the wolf once safely inside a shelter.
- **Story mechanics (Dungeon Master model)**: defined the Storyteller as a dungeon-master-style conductor and the pig and wolf agents as players, as in a tabletop RPG. The Storyteller opens the story with a narrating paragraph and, after each paragraph, decides whether to narrate more context or call on a character, who then takes exactly one action for their turn.
- **Improv "yes-and" rule**: added Rule 3 to `.claude/instructions.md` requiring all agents to accept and build on whatever another agent introduces into the story, rather than blocking or denying it.
- **Story scope objective**: set the goal that the improvised story should fit a double-spread comic book page, with the Storyteller nudging scenes toward resolution rather than letting them sprawl into a full-length story.
- **Repository scaffolding**: added `README.md` and this `JOURNAL.md` at the project root, and created the `journal-keeper` agent, responsible for maintaining this journal going forward.
- **Journal relocated into `.claude/`**: moved this journal from the project root into `.claude/JOURNAL.md`, so it lives alongside the rest of the agent configuration rather than as a repo-facing document. Updated `README.md` and `journal-keeper.md` to reference the new path.
- **Journal reading requirement**: added Rule 4 to `.claude/instructions.md` requiring every agent to read `.claude/JOURNAL.md` as part of its working context before acting, so the journal is treated as living background rather than optional reading.
- **Rules loaded automatically**: added a root `CLAUDE.md` that imports `.claude/instructions.md` and `.claude/JOURNAL.md`, because without it the shared rules were never loaded into sessions automatically. Each agent persona file also gained a line telling it to read and comply with both files, so spawned agents follow Rules 1–4 too.
- **Removed empty `context/` folder**: deleted the unused, empty `.claude/context/` folder, since nothing in the project referenced it.
- **Git initialized**: ran `git init` at the project root and added a `.gitignore` covering the in-project `tmp/` and `.scratch/` folders allowed by Rule 1, plus `.DS_Store`. No commit has been made yet.
- **Agents captured in `CLAUDE.md`**: expanded `CLAUDE.md` with a summary of the six agents and their roles, the shared pig action rules, and project conventions (keep the read-the-rules line in every agent file, journal each decision, keep scratch files in-project), so a new session starts with the full cast and rules in context without loading every persona file.
- **Project boundary made the first instruction everywhere**: made the project boundary rule the first section of `CLAUDE.md`, rewrote Rule 1 in `.claude/instructions.md` to match, and placed it as the first line of every agent file. No session or agent may check, read, copy, investigate, update, or delete anything outside the project folder; temporary files go only in the in-project `tmp/` folder and are deleted once no longer needed. This makes the rule explicit for subagents, which do not load `CLAUDE.md`.
- **Story output and running procedure**: a story request now always kicks off with the Storyteller, run by the main session as the game runner. Each story is saved to `screenwriting/YYYYMMDD.md` (with `-2`, `-3` suffixes for more stories on the same day) and printed live in the terminal, with every part labelled by the speaker's bolded name and a colon so the audience can follow it in order. The Storyteller ends each turn with a `Next:` line, may call any character repeatedly, and characters may only interact with others who are close by in the scene; otherwise the Storyteller carries the narrative on.
- **Chaos factor approved**: to make stories more chaotic, chose a real dice roll by the game runner over giving chaos to the Storyteller alone, to every character, or to a new Chaos agent, because language models are poor at being random by themselves and this spreads surprises across the whole cast. Before each turn after the opening, a four-sided die is rolled in the shell; a 1 hands that turn's agent a `CHAOS:` instruction to bring in something from outside the fable, capped at three chaos events per story (medium intensity). Added as Rule 5 in `.claude/instructions.md`, in the "Running a story" section of `CLAUDE.md`, and in each story agent's turn rules.
- **Turn length limits**: the first test run produced Storyteller paragraphs of around 180 words, far too long for a double-spread, so turns are now capped. A character's turn is at most 255 characters and should be a single short action or a quick thought or wonder; a Storyteller turn is at most 510 characters. The game runner checks each part's length and sends anything over the limit back to its agent to shorten.
- **Timestamped story file names**: story files are now named `screenwriting/YYYY-MM-DD_HH-MM.md`, using the date and 24-hour time the story started, so names stay human readable and sort chronologically from A to Z. Colons are avoided because macOS does not allow them in file names. The first test story was renamed to `2026-10-16_10-41.md` to match its creation time.
- **Refinements after the second test story**: the second test ran to 11 parts with all three chaos events, but the Bricks Pig never acted, the runner had to push for an ending by hand, a dragon repeated from the first story, and the Storyteller slowed down by rereading files every turn. Stories now have at most 12 parts, with the Storyteller told its part number and wrapping up from part 9; every pig and the wolf must act at least once; agents read the rules and journal on their first turn and only the story file after that; and `.claude/chaos-used.md` tracks past chaos elements so agents are told what to avoid.
- **Runner helper made permanent**: the temporary script used in the second test became `.claude/tools/turn.py`, which creates the story file, checks each turn's length, saves it in the speaker format, and rolls the chaos die, so every story runs the same way.
- **Simpler language**: all agent files were rewritten in short, plain sentences, and the characters and Storyteller are now told to use simple, everyday words, with the Storyteller keeping its drama in the tone rather than in long or fancy words. The "Running a story" section of `CLAUDE.md` was rewritten as six short steps.
- **Fixes after the third test story**: the third test worked well (everyone acted, it ended by itself at part 11, and chaos picks were all new), but the Storyteller slowed from about 14 seconds to 3.5 minutes per turn, still acted for the characters, and the runner once called an agent before checking the chaos roll. Now agents read no files after their first turn and the runner pastes in the new parts instead; the Storyteller is told never to decide what a pig or the wolf does and to share turns around; and `turn.py add` rolls the chaos die automatically after saving each turn, counts chaos events per story from `.claude/chaos-used.md`, and prints the list to avoid, with a new `turn.py chaos` command to record each element.
- **End-of-session wrap-up**: rewrote `README.md` to describe the current game (turn and length limits, simple language, chaos rolls, how to start a story) and the full project structure. Three test stories are kept in `screenwriting/` as a record of how the rules evolved. The latest fixes are untested in a full story, and nothing has been committed to git yet.

## 2026-10-23

- **Fourth test story**: `2026-10-23_10-12.md` ended by itself at part 11, every pig and the wolf acted, and all three chaos picks were new (Pinocchio, the Seven Dwarfs, Goldilocks). But three outside characters made the story confusing, the wolf never huffed or puffed, and the Storyteller wrote 6 of the 11 parts. It also showed a bug: when chaos rolled twice in a row, the next roll ran before the first element was recorded, so the event count and the avoid list were wrong.
- **Shorter, simpler stories**: every turn, the Storyteller's included, is now at most 125 characters, written so a 10-year-old can read it. Without the summary, a story must fit on one page.
- **Storyteller moved to the background**: the Storyteller opens the story, then runs the rounds like a game master, usually passing the turn with only a `Next:` line. It speaks in the middle only now and then (about twice at most) to switch scenes or fold in chaos. It closes on a cliffhanger to make readers curious about a next chapter, then writes a summary paragraph of up to 255 characters covering the start, middle, ending and cliffhanger, saved as `**Summary:**`.
- **One new chaos element per story**: the first chaos event brings in one character or object from another story; after that, nobody may add anything new, and later chaos events are twists that use what is already in the story in a creative way (for example, a glass slipper used to trick the wolf). Chaos always goes to a player, never the Storyteller. The pigs' and the wolf's goals stay the same.
- **`turn.py` updated**: one 125-character limit (255 for `Summary`), a `--chaos` option on `add` that records the element or twist before the next roll (fixing the bug above, and replacing the separate `chaos` command), twists logged as `twist:` lines in `.claude/chaos-used.md` and left out of the avoid list, and separate CHAOS new element and CHAOS twist messages.
- **Fifth test story, first with the new rules**: `2026-10-23_10-44.md` ran to 12 parts plus a summary, and the whole file is about 1,800 characters, well within one page. Every turn fit the 125-character limit on the first try, in simple words. The Storyteller wrote 4 of the 12 parts (the opening, one scene switch, one line folding in the chaos, and the closing cliffhanger) and passed the turn silently 5 times. Chaos rolled once and brought in a single element, Jack's magic bean, which the Wolf then used creatively by climbing the beanstalk; nothing else new was added. The cliffhanger came from the story itself (the wolf spots the Sticks Pig alone), and the summary covered start, middle, ending and cliffhanger in 215 characters. Minor notes, accepted as fine for now: the wolf never huffed and puffed, the Sticks Pig acted only once, and the runner asked for the closing line and the summary in one message to save a round trip.
- **Next phase proposed**: added a "Next steps" section to `README.md` with a draft plan to turn finished stories into a one-page comic (later a double spread) using only Claude: art drawn as SVG in a simple flat style, and a pipeline of script editor, art director with a shared character sheet, panel artists, letterer, layout and critic agents. It is a proposal only, to be revised in the next session; nothing has been built yet.

It is the style Claude draws most cleanly in code and keeps characters consistent between panels. Image-generation models and a hand-made cast sheet were discussed as alternatives but not chosen, to keep the story machine Claude-only and free to run.
- **Monoline drawing rules**: drawings are built on a grid from circles, arcs and straight lines, with one vanishing point for perspective; each object gets a thin white halo so lines stop cleanly instead of crossing, and the parts of one character merge into a single outline. The test scene is in `tmp/style/` and is not yet part of the project.
